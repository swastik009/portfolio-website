## What we decided, and why

- **The login dialog goes.** Its only job was satisfying browser autoplay policy. Audio unlock
  needs *sticky activation*, which any `click` / `touchend` / `keydown` grants — so the gesture can
  be disguised as anything. It becomes Clippy on a black screen asking to boot the PC.
- **Both gate buttons boot.** "No thanks" earns *"Booting anyway. I'm an assistant, not a
  democracy."* first. Any gesture unlocks audio, so both buttons must lead somewhere — the joke is
  the requirement.
- **Sticky activation dies on every page load**, so the gate is permanent. Only the *boot
  animation* is skippable, via `localStorage` for 10 days.
- **1:1 in space, compressed in time.** Every POST frame is pixel-faithful to the reference video;
  only the dwell shortens. ~6s total.
- **Mobile is untouched** — it skips the gate entirely and keeps its current screen. It never
  played the startup sound, so it needs no gesture, and a phone should not download a 1.27MB
  sprite for nothing.
- **Dropped:** Winamp (revisit only when functional), screensaver gate and idle screensaver.

## Findings worth not rediscovering

- `dist/app.min.js` is minified **`personal_win.js`** (not `boot.js`). Verified byte-reproducible
  with `npx terser personal_win.js -c -m`. The April spec says the opposite — it is wrong.
- `boot.js` is dead: a byte-identical copy of `personal_win.js` lines 1–72, referenced by nothing.
  Task 9 deletes it.
- `agents/Clippy/map.png` **cannot be compressed.** Already an 8-bit colormap PNG. pngquant makes
  it *larger* (1.37MB vs 1.33MB); lossy WebP 2.3MB; lossless WebP 1.36MB. Don't retry this.
- `clippy.js` `Balloon.speak()` uses `.text()` and types word-by-word — no HTML inside the balloon.
  `speak(text, true)` holds it open; append buttons as a sibling inside `.clippy-balloon`.
- `agent.gestureAt(x, y)` auto-picks the directional animation. 43 animations available.
- Startup mp3 is **7.92s**, longer than the boot. It starts at the wipe and rides onto the desktop.
- Clouds wipe measured at **~950ms, linear, bottom-anchored upward reveal** (`clip-path: inset()`).
- Playwright resolves from `/Users/swastik/node_modules` with cached Chromium. Works today.
- ffmpeg SSIM discriminates sharply: 0.9997 identical vs 0.027 different. That's the fidelity metric.

## Blockers to clear before or during Task 1

1. **Font download** (Task 3, Step 1) — Px437 IBM VGA 8x16 from int10h.org. If the URL 404s,
   **stop and ask** rather than substituting a different font. The font *is* the fidelity.
2. **The reference video.** `windows-98-boot-animation.mp4` (877KB) is currently untracked.
   Task 12's fidelity test needs it present. Decide: commit it so the test is reproducible from a
   clean clone, or keep it local and gitignored. **Owner's call — ask.**
3. **`icons/epa.png` is untracked.** The boot markup in Task 2 and the POST in Task 6 both
   reference it. It exists in the working tree (pulled from `feat/win98-boot-mobile`) so local work
   is fine, but it must be `git add`ed before the first push or the deployed POST loses its Energy
   Star logo. `icons/reference.boot.png` is also untracked — unused; delete or keep as reference.
4. **The `clippy.js` patches.** The owner hand-fixed issues in the vendored library. Ask what was
   changed before extending balloon or positioning behaviour, in case Task 5 collides with it.

## Rules that will bite

- **Never push a red build.** Cloudflare deploys on push. `node .smoke.cjs && node .fidelity.cjs`
  must both be green first.
- **Never add `package.json`** — Cloudflare Pages would detect it and try to run a build.
- **Never refactor `assets/js/clippy.js` or `agents/Clippy/*`.**
- After any `personal_win.js` edit: re-run terser AND bump the `?v=` cache-buster.
- Implement on a fresh branch off `master`. `feat/win98-boot-mobile` is superseded — Task 8
  cherry-picks its two splash images, then abandon it.
